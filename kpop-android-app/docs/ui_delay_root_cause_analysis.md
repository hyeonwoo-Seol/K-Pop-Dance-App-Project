# UI 지연/버벅임 원인 분석

## 1) 첫 실행 로그인 후 `닉네임/생년월일` 화면 전환이 느린 이유

### 관찰된 흐름
1. 로그인 버튼 클릭 시 `signInWithEmail()`를 먼저 await 합니다.
2. Firebase 인증이 성공하면 그 다음에 `checkUserExists()`를 호출합니다.
3. `checkUserExists()` 내부에서 Room DB의 `getUserProfileOneShot()`를 조회해 신규/기존 유저를 분기합니다.
4. 신규 유저이면 `NeedProfile` 상태로 바뀌고, 이때 추가 정보 입력 화면(회원가입 2단계)으로 이동합니다.

### 지연으로 보이는 이유(추론)
- **로딩 상태(`LoginState.Loading`)가 `signInWithEmail()` 이후에만 켜집니다.**
  - 즉, 네트워크(Firebase 인증) 대기 시간 동안은 버튼이 일반 상태로 보일 수 있어 "멈춘 듯한 딜레이"로 체감됩니다.
- **첫 실행 시점에는 DB 시드 작업이 동시에 발생할 가능성**이 있습니다.
  - 앱 시작 시 `prePopulateSongsIfNeeded()`를 백그라운드에서 실행하고,
  - 로그인 이후 `loadInitialData()`에서도 같은 시드 함수를 다시 호출합니다.
  - 초회 실행 시 곡/파트 insert가 겹치면 DB 접근 체감 지연이 커질 수 있습니다.
- **신규 유저 판단이 Firebase가 아니라 로컬 Room 기준**이라, 인증 성공 직후에도 로컬 조회/상태전환 단계를 한 번 더 거칩니다.

## 2) 홈 검색에서 결과는 즉시 나오는데 키보드가 늦게 닫히는 이유

### 관찰된 흐름
1. 홈 화면 검색창 `IME Search` 액션에서 `onSearch(searchText)`만 호출합니다.
2. 이 콜백은 바로 `navController.navigate("searchResults/...")`를 수행합니다.
3. 홈 화면 코드에는 `clearFocus()`나 `keyboardController.hide()`가 없습니다.

### 지연으로 보이는 이유(추론)
- 검색 결과는 라우팅 직후 바로 그려지지만,
- **키보드 닫힘은 "포커스 해제/입력 연결 종료" 타이밍에 의존**합니다.
- 현재는 명시적 키보드 닫기 없이 화면 전환만 하기 때문에,
  - 기기/IME 조합에 따라 한 박자 늦게 닫히는 현상이 쉽게 발생합니다.
- 추가로 검색결과 화면 자체에도 `OutlinedTextField`가 있어,
  - 전환 직후 IME가 잠깐 열린 상태를 유지하는 체감이 생길 수 있습니다.

## 3) `프로필 설정`만 스크롤이 끊기는 이유

### 구조 비교 관찰
- `프로필 설정`은 단일 화면에 다음이 한 번에 들어갑니다.
  - 프로필 이미지 카드(이미지 로딩)
  - 기본정보 입력 `OutlinedTextField` 다수
  - 드롭다운, `FlowRow + FilterChip` 다수
  - 멀티라인 입력 + 글자수 카운터
  - 하단 고정 저장 바 + 투명 Scaffold 위 그라데이션 배경
- 반면 `연습 화면 설정`, `앱 정보`는 텍스트/토글 중심으로 상대적으로 단순합니다.

### 끊김으로 보이는 이유(추론)
- **입력 컴포넌트(OutlinedTextField)와 칩/드롭다운이 많아 측정/레이아웃 비용이 큼**
  - 특히 `FlowRow` + 여러 `FilterChip`은 폭 재계산이 빈번합니다.
- **상태 소스가 많고(`currentUserProfile`, `userStats` + 로컬 mutableState 다수) 재구성 범위가 큼**
  - 스크롤 중 상태 이벤트가 오면 전체 트리 재구성이 체감될 수 있습니다.
- **이미지 디코딩/렌더링 + 투명 레이어/그림자 조합**으로 GPU/Overdraw 부담이 상대적으로 큽니다.

---

## 결론(요약)
- 1번은 **인증 await + 로딩 표시 시점 + 초회 DB 시드 작업 겹침**이 주요 후보.
- 2번은 **검색 액션에서 키보드/포커스를 명시적으로 닫지 않는 구조**가 가장 유력.
- 3번은 **프로필 화면만 UI 구성요소 복잡도와 재구성 비용이 높아 발생하는 렌더링 부하**가 유력.
